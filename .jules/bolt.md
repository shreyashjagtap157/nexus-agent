
## 2024-06-15 - [Replace slow pathlib.rglob with fast os.scandir for directory traversals]
**Learning:** Using `pathlib.Path.rglob()` for recursive directory traversal creates significant overhead because it creates intermediate `Path` objects. A custom recursive `os.scandir` implementation is much faster for tasks like finding GGUF files and calculating disk usage, especially when handling deeply nested folders.
**Action:** When optimizing file system traversal or repeated `stat` checking in hot loops, prefer `os.scandir` with explicit `follow_symlinks` flags instead of `pathlib.rglob()`.
## 2024-06-25 - [Optimize Path.glob with any() for Existence Checks]
**Learning:** Using `list(path.glob("**/*.py"))` just to check if files exist creates unnecessary overhead by forcing a complete directory traversal and loading all matching paths into a list. This is exceptionally slow for deeply nested directories or large numbers of files (O(N) time/space).
**Action:** When only checking for file existence, replace `list(path.glob(...))` with short-circuiting generators using `any(True for _ in path.glob(...))` to achieve O(1) best-case performance for both time and memory. Additionally, note that Python ternary operator precedence makes `A or B if C else D` evaluate as `(A or B) if C else D`; when mixing `or` with conditionally executed globs, use explicit boolean structures like `A or (C and B)` instead of the ternary operator to prevent logic bugs.

## 2026-10-08 - [Mock target matching dependency in sys.modules]
**Learning:** When using `patch.dict('sys.modules', {'module_name': None})` to simulate an uninstalled package, the mocked module name must exactly match the internal dependency code evaluates. Copy-pasting a mock for one package (e.g., `jax`) to simulate the absence of another (e.g., `openvino`) may pass locally if the target package is genuinely uninstalled, but will fail in CI pipelines where the target package is fully present, because the real import is never intercepted. Additionally, mocking `sys.modules` isn't foolproof against `importlib.util.find_spec`, so both should be patched.
**Action:** Always ensure the string key in `patch.dict('sys.modules', {'<key>': None})` accurately targets the dependency being tested, and supplement it with `patch('importlib.util.find_spec', return_value=None)` for comprehensive dependency isolation.
