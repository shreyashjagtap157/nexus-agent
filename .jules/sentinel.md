## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.

## 2024-06-22 - Improved Cross-Site WebSocket Hijacking (CSWSH) protection
**Vulnerability:** Hardcoding allowed localhost origins for WebSocket CSWSH protection can introduce functional regressions when a server is configured to accept connections on remote hosts (e.g., using `--host 0.0.0.0`). Additionally, blocking all requests without an `Origin` header breaks legitimate programmatic access.
**Learning:** Security fixes must balance protection with operational flexibility. For CSWSH, it is safer to dynamically compare the `Origin` header against the `Host` header of the incoming request. If they match, the origin is safe regardless of whether it's localhost or a custom remote hostname. Furthermore, programmatic API clients and tools rarely send an `Origin` header; these can generally be allowed because they aren't subject to the browser-based Cross-Site request risks that `Origin` validation protects against.
**Prevention:** In WebSocket endpoints, only validate and reject the `Origin` header if it is actually present in the request. When validating it, extract the requested hostname from the `Host` header (`websocket.headers.get("Host")`) and add it to the set of allowed hostnames (alongside `127.0.0.1` and `localhost`).
