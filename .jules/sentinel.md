## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.
## 2024-05-24 - SQL Wildcard Injection in SQLite LIKE Queries
**Vulnerability:** Unsanitized user input in parameterized SQLite `LIKE` queries allowed wildcard characters (`%`, `_`) to alter query logic, and more critically, the backslash (`\`) escape character itself was not being escaped, leading to potential `sqlite3.OperationalError` exceptions when user input ended with a backslash.
**Learning:** When mitigating SQL wildcard injection in SQLite by using `ESCAPE '\'`, the backslash character itself must be escaped *before* escaping the wildcard characters, because Python's string replacement applies sequentially and can leave trailing unescaped backslashes in the SQL string, which SQLite interprets as a syntax error in the `ESCAPE` clause.
**Prevention:** Always escape the escape character first: `query.replace("\\", r"\\").replace("%", r"\%").replace("_", r"\_")`.
