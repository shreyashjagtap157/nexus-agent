## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.

## 2024-06-24 - Fix missing Origin validation in WebSocket endpoint
**Vulnerability:** The WebSocket endpoint `/api/ws/{session_id}` in `server.py` accepted connections indiscriminately without validating the `Origin` header. This exposed the application to Cross-Site WebSocket Hijacking (CSWSH), allowing malicious websites to establish a connection to the local agent's WebSocket and potentially control or eavesdrop on sessions.
**Learning:** WebSocket endpoints in FastAPI are not automatically protected by CORS middleware against CSWSH. While standard HTTP endpoints are protected by `CORSMiddleware`, WebSockets require explicit origin validation in the connection handler because the browser's Same-Origin Policy does not prevent WebSocket connections from being initiated by other domains.
**Prevention:** Always validate the `Origin` header explicitly within the WebSocket endpoint logic (e.g., using `urllib.parse.urlparse` to verify the hostname against allowed origins) before calling `await websocket.accept()`.
