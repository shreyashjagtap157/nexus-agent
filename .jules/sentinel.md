## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.
## 2026-07-15 - CSWSH Prevention in FastAPI WebSocket Endpoints
**Vulnerability:** Cross-Site WebSocket Hijacking (CSWSH) could allow malicious websites to establish authenticated WebSocket connections if standard origin validation is missing.
**Learning:** `WebSocketException` inherits from `Exception`. If a generic `except Exception` block wraps the handler loop, throwing `WebSocketException` to cleanly reject origins gets incorrectly trapped and swallowed, preventing the socket from closing and muddying logs.
**Prevention:** Always validate `websocket.headers.get("origin")` explicitly against `websocket.headers.get("host")` before `await websocket.accept()`. Import and raise `WebSocketException`, and if you have a top-level `except Exception:` block, make sure to add an explicit `except WebSocketException: raise` block *above* it to preserve standard ASGI closure mechanisms.
