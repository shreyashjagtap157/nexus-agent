## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.

## 2024-05-18 - CSWSH protection in local FastAPI WebSockets
**Vulnerability:** The local WebSocket endpoint (`/api/ws/{session_id}`) did not validate the `Origin` header against the `Host` header. This exposed the application to Cross-Site WebSocket Hijacking (CSWSH), where an attacker-controlled website could establish a WebSocket connection to the local agent server and send/receive commands on the user's behalf.
**Learning:** Even for local-only servers (binding to `localhost` or `127.0.0.1`), WebSocket endpoints are vulnerable to cross-origin requests from malicious sites running in the user's browser, because WebSockets do not respect the Same-Origin Policy (SOP) by default. Additionally, checking for `origin == "null"` is necessary because data URIs and local HTML files send a "null" origin.
**Prevention:** Always validate the `Origin` header against the expected `Host` header (extracting the hostname via `urllib.parse.urlparse` for the origin and string splitting for the host) in WebSocket connection handlers. Deny connections where `origin == "null"` or where the hostnames do not match.
