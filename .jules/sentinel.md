## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.
## 2024-05-18 - Fix wildcard injection in SQL LIKE query
**Vulnerability:** The RAG search tool (`src/nexus_agent/tools/rag_search.py`) passed user queries directly to a parameterized `LIKE` clause with `%` wildcards without escaping literal `%` and `_` characters in the user input.
**Learning:** Even when parameterized queries protect against classic SQL injection (SQLi), failing to escape SQL wildcards in user input can lead to logic bugs, data exposure, and ReDoS-style denial of service issues (wildcard injection). Furthermore, the escape character itself (e.g., `\`) must also be escaped prior to the wildcards.
**Prevention:** When mitigating SQL wildcard injection for parameterized `LIKE` queries (e.g., in SQLite), ensure the escape character itself (`\`) is escaped before escaping the wildcard characters (`%` and `_`) to prevent bypasses and logic bugs (e.g., `query.replace("\\", r"\\").replace("%", r"\%").replace("_", r"\_")`).
