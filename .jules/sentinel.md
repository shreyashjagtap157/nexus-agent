## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.

## 2024-06-20 - Fix Cross-Site WebSocket Hijacking (CSWSH) in local GUI server
**Vulnerability:** The FastAPI WebSocket endpoint for the local GUI server (`/api/ws/{session_id}`) did not validate the `Origin` header. Since WebSocket connections are not restricted by CORS policies by default, a malicious website could initiate a WebSocket connection to the local server (e.g., `ws://127.0.0.1:7860/api/ws/...`) if the user is running the GUI, allowing the attacker to read and write arbitrary messages to the local agent session.
**Learning:** While HTTP endpoints are protected by CORS middleware, WebSocket endpoints in FastAPI require manual `Origin` validation. The assumption that local servers are safe from remote attacks is false if they don't protect against cross-site requests.
**Prevention:** Always extract and validate the `Origin` header inside the WebSocket endpoint handler against an explicit allowlist (e.g., `http://localhost`, `http://127.0.0.1`) before calling `websocket.accept()`. Close the connection with `status.WS_1008_POLICY_VIOLATION` if the origin is untrusted.
