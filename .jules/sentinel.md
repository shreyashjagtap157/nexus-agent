## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.
## 2024-05-24 - Fix Windows cmd.exe command injection in Sandbox
**Vulnerability:** The Sandbox execution on Windows used `cmd.exe /c` with `shlex.split()` parsed arguments, but did not filter Windows-specific shell metacharacters. This allowed command injection because `cmd.exe` interprets characters like `&` and `|` even when they are part of a quoted argument or an argument list.
**Learning:** When using `cmd.exe /c` to execute commands (which is necessary for Windows shell built-ins like `dir`), passing arguments as a list via `subprocess.run` does not provide the same isolation as it does on Unix shells. `cmd.exe` still parses the command line string for its metacharacters.
**Prevention:** Explicitly reject arguments containing Windows shell metacharacters (`&`, `|`, `<`, `>`, `^`, `%`, `\n`, `\r`) before executing the command with `cmd.exe /c` to prevent injection while maintaining support for built-ins.
