## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.

## 2024-05-20 - Fix Cross-Site WebSocket Hijacking (CSWSH) in GUI Server
**Vulnerability:** The FastAPI WebSocket endpoint `/api/ws/{session_id}` in the GUI server lacked `Origin` header validation against the `Host` header. This allowed any external website to establish a WebSocket connection and potentially execute commands as the user through the agent tools if the victim visited a malicious site while running the agent locally.
**Learning:** WebSocket connections initiated from web browsers carry credentials (like cookies) and allow full bidirectional communication, but bypass the Same-Origin Policy (SOP). FastAPI's generic `WebSocket` does not validate origins by default, unlike CORS middleware for HTTP. Generic exception handlers (like `except Exception:`) can also inadvertently catch internal framework exceptions like `WebSocketException`, preventing proper closure sequences.
**Prevention:** Always extract and validate the `Origin` header against the expected `Host` or a specific list of allowed origins before calling `websocket.accept()`. Compare hostnames securely by correctly parsing out ports and IPv6 brackets. Ensure `fastapi.WebSocketException` is explicitly handled or re-raised if a catch-all exception block is present in the route handler.
