## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.
## 2024-05-18 - Fix excessive file traversal on checkpointing
**Vulnerability:** The application used `pathlib.Path.rglob` for file discovery in checkpointing and interactive features, which could lead to high CPU, massive intermediate Path object allocations, and out-of-memory errors on large directory structures with heavy `node_modules` or build directories, creating a local Denial of Service (DoS) risk.
**Learning:** High-level APIs like `pathlib.rglob` or greedy file traversal operations without depth limits and proper early exits on matching sizes can easily become unintentional DoS vectors in massive monolithic repositories.
**Prevention:** In system utilities scanning arbitrarily large directories, use low-level lazy APIs like `os.scandir()` accompanied by explicit filter logic and early exits.
