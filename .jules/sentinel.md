## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.
## 2024-05-18 - Fix wildcard injection in RAG code symbol search
**Vulnerability:** The offline RAG SQLite search query for `code_symbols` used `LIKE ?` with `f"%{query}%"` without escaping user-supplied `%` or `_` characters. While parameterized queries (`?`) prevent full SQL injection (so an attacker can't break out of the string), allowing unescaped wildcards can lead to slow queries (ReDoS equivalent) or over-fetching sensitive symbols.
**Learning:** Even when using parameterized queries to protect against SQL injection, you must escape `LIKE` wildcards (`%` and `_`) using the `ESCAPE` clause to prevent application-level logic bypasses or Denial of Service through excessive pattern matching.
**Prevention:** Always sanitize inputs meant for `LIKE` clauses by escaping wildcard characters and specifying an explicit `ESCAPE` character.
