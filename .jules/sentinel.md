## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.

## 2024-07-05 - Fix Cross-Site WebSocket Hijacking (CSWSH) in GUI Server
**Vulnerability:** The FastAPI WebSocket endpoint in `src/nexus_agent/gui/server.py` lacked validation of the `Origin` header. This allowed malicious external websites to silently connect to the local NexusAgent instance via WebSocket (`ws://localhost:7860`), bypassing CORS restrictions and potentially executing arbitrary local code on the user's machine.
**Learning:** WebSockets do not respect the Same-Origin Policy (SOP) or CORS configurations by default. A local web server with an open WebSocket endpoint is highly vulnerable to CSWSH. Programmatic clients (CLI) might omit the `Origin` header entirely, while browsers guarantee its presence. Local file execution might use `Origin: null`.
**Prevention:** Implement strict `Origin` validation for all WebSocket endpoints. Extract the `Origin` hostname and explicitly verify it matches the expected server `Host` header. Ensure `Origin: null` is explicitly rejected. Allow connections where the `Origin` header is absent entirely to support programmatic non-browser clients. When parsing the `Host` header, correctly extract IPv6 addresses without ports.
