## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.
## 2026-09-20 - Fix SQL LIKE wildcard injection in SQLite escaping logic
**Vulnerability:** SQLite FTS queries falling back to `LIKE` statements attempted to escape wildcard characters `%` and `_` using `\`. However, they failed to escape the backslash escape character itself (`\`). This allowed an attacker to input strings like `\%`, neutralizing the injected backslash and bypassing the intended literal wildcard escaping.
**Learning:** When mitigating SQL wildcard injection in parameterized `LIKE` queries by manually injecting escape characters (e.g. `\`), the escape character must always be escaped first (e.g., `query.replace('\\', r'\\')`) before replacing the target wildcards.
**Prevention:** Ensure any manual string replacement designed to neutralize SQL wildcards processes the escape character itself first before targeting the `%` and `_` characters.
