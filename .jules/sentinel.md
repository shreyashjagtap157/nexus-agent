## 2024-05-18 - Fix command injection in Sandbox fallback
**Vulnerability:** The command isolation sandbox (`Sandbox.execute`) fell back to executing commands via `sh -c` or `powershell` with unparsed string commands when `shlex.split()` failed to parse due to unmatched quotes or syntax errors. This bypasses array-based shell escaping and presents a command injection vulnerability.
**Learning:** Fallbacks intended to improve developer experience (e.g., executing malformed strings in a subshell) can completely undermine the primary security isolation mechanism if they revert to inherently unsafe functions like `sh -c`.
**Prevention:** If the safe parsing mechanism (`shlex.split()`) fails to interpret input securely, the operation must be rejected entirely rather than passed on to a less secure evaluation layer.
## 2026-05-31 - Cross-Site WebSocket Hijacking (CSWSH) in GUI Server
**Vulnerability:** The FastAPI GUI server's WebSocket endpoint (`/api/ws/{session_id}`) did not validate the `Origin` header. Although standard HTTP requests were protected by CORS middleware restricting access to `127.0.0.1` and `localhost`, WebSocket connections do not inherently enforce CORS. This allowed a malicious website to open a WebSocket connection to the local agent, bypassing CORS, and interact with the user's local shell and files via the agent's tools.
**Learning:** WebSocket endpoints in web frameworks (like FastAPI) often require manual `Origin` header validation, even if global CORS middleware is configured, because the WebSocket protocol handshake is different and standard browser CORS restrictions don't always fully apply to the persistent connection setup in the same way they do for XHR/Fetch.
**Prevention:** Always explicitly validate the `Origin` header during the WebSocket handshake (`await websocket.accept()`) against an allowed list of domains, matching the application's CORS policy.
